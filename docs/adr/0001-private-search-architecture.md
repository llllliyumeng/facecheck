# ADR 0001：密文域人像检索的威胁模型与原型选择

- 状态：研究决策已记录；生产算法选择暂缓
- 日期：2026-11-01
- 背景：FaceCheck 当前上传后以 SM4-CBC + HMAC-SM3 分块存储；检索时由可信服务端认证、解密/恢复并执行明文特征检索。认证恢复结果与明文分数一致，不能证明密文相似度计算或 ANN 安全。

## 1. 保护对象和攻击者

### 保护对象

- 视频明文、查询图像、人脸向量和人脸关联的身份 ID。
- SM4/SM3 主密钥、逐对象数据密钥、SM2 接收方私钥和密钥版本状态。
- 查询内容、候选集合、排序结果、访问频率及对象关联关系。

### 必须考虑的攻击者

1. 仅能读取对象存储和数据库的云存储管理员：不应获得视频/向量明文或密钥。
2. 可观察服务端存储、索引和请求元数据的好奇云运营者：需明确是否会看到查询重复性、访问对象、返回数量、响应时间或结果 ID。
3. 未授权 API 客户端：不能读取其他用户视频、提交越权查询或借错误响应推断密钥有效性。
4. 获得一次查询结果的授权用户：需讨论其能否长期关联身份、缓存或推断其他人的模板。

### 当前明确不覆盖的攻击者

- 同时完全控制应用进程、运行内存、OS/虚拟机监控器、数据库、对象存储和密钥保管系统的攻击者。
- 对侧信道、硬件故障、恶意模型和终端被植入的完整防护。若后续选 enclave/TEE，需要把这些威胁重新纳入并做设备级评估。

## 2. 当前信任边界与已知泄漏

- HTTPS 保护传输；SM4-CBC + HMAC-SM3 保护持久化视频与特征缓存。
- 检索服务在认证后恢复视频，或解密已认证的特征缓存，再对明文特征做 cosine/max 排序。因此应用主机内存、进程、管理员调试接口和崩溃转储处于可信计算边界。
- 组织级角色检查提供基本 API 授权，但当前无多租户/逐视频所有者隔离。
- 审计和 benchmark 会暴露操作时间、任务 ID、数量等元数据；审计导出本身没有外部不可变锚点。
- 这些边界不满足“云运营者不可见向量或查询”的强密文检索目标。部署在云端、向量文件使用密钥加密，不能单独改变这一结论。

## 3. 备选方案

| 方案 | 内容保护 | 可能泄漏/成本 | 适用定位 |
|---|---|---|---|
| 服务端解密后 HNSW/FAISS | 静态对象加密；查询执行期依赖服务端可信 | 服务端内存见明文；近似 ANN 快，但不满足云运营者不可见特征 | 当前功能基线和性能上限，不称密文检索 |
| TEE/机密虚拟机内 ANN | 将特征、查询和排序限制在受硬件保护执行环境内 | 依赖 CPU/云厂商信任根、远程证明和补丁；需评估侧信道、页访问/输出长度泄漏；TEE 内仍处理明文 | 有目标硬件与远程证明后评估的工程型隐私方案；名称应为受信执行，不称纯密文计算 |
| 同态加密点积/相似度 | 服务器可对密文做指定运算，保护特征和查询内容 | 密文排序/top-k、ANN 建图和结果选择成本高；候选访问模式及 ID 返回仍可能泄漏 | 小规模精确相似度 correctness baseline，后续按真实复杂度测试 |
| 结构化可搜索加密/倒排或量化索引 | 可针对查询结构隐藏部分明文 | 常泄漏查询重复性、访问模式、结果数量或相似访问关系；需明确泄漏函数 | 只有数据所有者接受显式泄漏预算时再比较 |
| MPC/秘密分享 | 多计算方下分散单方可见信息 | 通信轮次、协同方假设和 ANN 复杂度可能与 2 秒目标冲突 | 多方不串谋假设明确且基础设施可用时研究 |

## 4. 决策

**暂不选定生产密文 ANN 算法，也不把 TEE、磁盘加密或当前 encrypted_restore 冒称为密文域检索。** 先冻结本 ADR 的攻击者与泄漏问题，并用三条可比较路径做研究：

1. plaintext exact/ANN 基线，用于测量精度和延迟上限。
2. 小规模同态相似度基线，用于验证加密向量、加密查询、分数解密和 Top-K 的端到端正确性；基线规模可从 20/100/1,000 个向量逐步扩展，不预先承诺 10 万对象或 2 秒。
3. 有目标机密计算硬件后测 TEE ANN；记录远程证明、内存隔离配置、服务端可见字段和侧信道评估范围。TEE 结果必须标为受信执行。

结构化可搜索加密仅作为候选。若进入实验，先定义并报告查询重复、候选访问、结果 ID/数量、访问频率泄漏，不能只报告 Top-1。

生产系统继续使用当前认证恢复后的明文检索路径，并在接口/报告中说明信任边界。任何新原型与现有路径隔离，避免破坏既有格式和正式实验。

## 5. 原型验收协议

实现之前先固定以下测量定义：

- **准确性**：同一批查询、同一身份划分、同一冻结模型和阈值；报告明文 Top-1、TAR@FAR、密文方案 Top-1 相对明文下降的百分点，并保留全部拒绝/未评分项。
- **结果一致性**：分别报告 Top-1 身份一致率、Top-K 候选/排序一致率、相似度误差分布。三者不得合并成未定义的“结果一致率”。
- **性能**：分别测索引构建、冷查询、热查询、解密/安全计算、Top-K 和端到端延迟；报告 P50/P95、并发度、数据规模、设备和库版本。
- **安全性**：云存储/数据库被单独读取、API 越权、查询重复、访问模式和结果 ID 观察等攻击场景逐项验证；列出所有仍泄漏字段。
- **通过门槛**：必须在预先指定规模上达到 Top-1 下降≤2 个百分点、查询延迟/误差符合验收协议，且泄漏表经项目负责人接受。小数据正确性样例不视为课题指标通过。

## 6. 重新打开决策的条件

- 项目明确云服务商/OS/应用主机中哪些角色不可信，以及可接受的查询/访问模式泄漏。
- 有目标规模的授权数据、设备或机密计算环境及可用国密/安全计算实现。
- 原型数据说明精确 HE、TEE 和 SSE 的误差/性能/泄漏权衡后，项目接受其中一种具体威胁边界。
