# 审计事件本地完整性链原型

## 已实现

`TaskRepository._audit()` 是所有应用审计事件的唯一写入路径。每条记录除原有字段外保存 `previous_hash` 与 `event_hash`。版本 1 使用 SHA-256，对固定字段的 UTF-8、排序键、紧凑 JSON 编码计算：

```text
SHA256("facecheck-audit-v1\0" || canonical_json(event_id, task_id,
       event_type, created_at, detail, previous_hash))
```

首条事件以前置固定 genesis hash 开始。写入在 SQLite `BEGIN IMMEDIATE` 锁内读取链尾、插入事件并计算摘要，避免并发写入分叉。旧库首次启动时按 `event_id` 顺序补齐已有事件的链字段；此操作只为迁移后的数据库建立基线，不证明迁移前从未发生过历史改写或删减。

接口与导出：

- `GET /api/v1/platform/audit/integrity`：返回本地全链检查结果、事件数量、首尾 ID、链头摘要以及失败位置。
- `GET /api/v1/platform/audit/export?format=json|csv|md`：事件行与校验状态从同一个 SQLite 读快照读取；筛选导出仍校验全库链。JSON/Markdown 包含校验摘要，CSV 首行是 `integrity_summary` 元数据行，后续为事件行。
- 原有 `GET /api/v1/audit` 事件记录增加 `previous_hash` 和 `event_hash`，可供客户端保留链证据。

## 可检测范围

如果攻击者只改写一条现有记录而不重算后续链，本地验证会在该行失败；中间事件被删除、行内容调换或链字段被改动，通常会在第一处链连续性不符处失败。旧库补链后新发生的同类变化也按相同逻辑检查。

## 未覆盖范围

摘要保存在与事件相同的 SQLite 文件中，没有外部可信锚点或签名。因此本原型**不能**证明尾部事件未被截断、数据库快照未被整体回滚，也不能抵御能同时修改数据库并重算全链的管理员/攻击者。它只提供本地篡改迹象检查，不是不可抵赖日志，也不证明 99.9% 完整率或 99% 导出成功率。报告导出后写入的 `audit_report_exported` 事件不属于刚导出的同一快照。

校验接口每次按 ID 顺序扫描整条事件链，时间开销为 O(n)；全量导出目前也会把匹配事件放入内存。该实现没有用大规模审计数据做延迟、内存或持续负载验收，不能据此宣称规模化能力。

下一步需要独立受控的远程锚点或不可变对象存储，周期性提交链头、事件数和可信时间；再通过断电/崩溃、删除/重排、整库恢复和双边对账测出完整率。该环境及验收数据目前缺失。

## 验收记录

`tests/test_audit_chain.py` 覆盖新链、并发写入、事件内容篡改、中间删除/重排、旧表迁移、HTTP 校验接口及三种导出状态。它验证的是当前 SQLite 原型的功能行为，不是生产日志可靠率或攻击成本。
