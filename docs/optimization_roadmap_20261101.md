# FaceCheck 优化清单与分阶段验收

核对范围：README、课程报告正文、YTF 正式 test 记录、指标 benchmark、云端 HTTPS 验证、`src/facecheck/` 中的存储、识别、安全、任务和平台实现。本文保留正式识别和性能基线，并记录后续小样本及阶段性实现；正式 test 和性能 benchmark 未重跑。

## 实现状态

| 类别 | 已有能力 | 边界或待补项 |
|---|---|---|
| 已实现 | SM4-CBC 视频分块、HMAC-SM3 上下文认证、SM3 用途/版本派生、认证后恢复、大小和 SHA-256 核验 | 这是全视频字节分块加密；不是编解码器感知的选择性加密。生产 v1 本地 manifest 没有独立 MAC/签名 |
| 已实现 | YuNet + ArcFace 默认识别、SFace 对照、identity-disjoint selection/test、阈值冻结和失败样本保留 | 正式 ArcFace test Top-1 86.06%、TAR 86.65%；均未达到课题目标 |
| 已实现 | HTTPS 云端启动、admin/operator/auditor 组织级权限、会话/凭据撤销、加密特征缓存、后台任务、审计导出 | 本机单实例验证；无远程持续负载或多租户隔离证据 |
| 部分实现 | SM2 加解密及签名接口、显式 opt-in 的 v2 逐视频密钥信封和 HMAC-SM3 manifest 原型 | 生产 Web/cloud 上传仍写 v1；缺可信证书/公钥目录、私钥 KMS 和数据库引用迁移 |
| 部分实现 | 版本化派生、v1 单视频重加密、v2 单/批量 rewrap 文件原型及原子进度 journal | 未接入服务任务队列/数据库原子切换；缓存、备份、副本和旧密钥全局撤销未覆盖，未证明“旧密钥失效率 100%” |
| 部分实现 | 视频密文和静态特征缓存的认证保护、SQLite 审计 SHA-256 链、快照校验和导出 | 特征没有可撤销变换；审计链无外部不可变锚点，尾部截断/整库回滚无法由本地链证明；完整率未测 |
| 未实现 | 密文域安全索引/ANN | 现有 `encrypted_restore` 先恢复明文，再做 cosine/max 检索 |
| 未实现 | 可撤销、跨库不可关联的人像模板 | 加密缓存是静态加密，不是可撤销模板 |
| 未实现 | 边缘设备推理和边缘—云协同协议 | 当前推理在服务端/本机 OpenCV CPU 路径执行 |
| 未测 | 10,000 人、100,000 段、1,000,000 帧综合集 | 当前 manifest 为 1,004 个身份、1,004 段 Gallery、1,004 张 Query、190,191 个 Gallery 源帧 |
| 未测/未达 | SM4、识别端到端响应、真实设备兼容、持续并发、日处理量、审计成功率和完整率 | 见下方新的机器可读核对结果及来源摘要 |

状态含义：`已实现`表示源码路径存在；`部分实现`表示只覆盖子功能或有限样本；`未实现`表示没有对应机制；`未测`表示没有符合目标口径的实验。小样本通过只记为部分证据。

## 分阶段工作

### 阶段 0：证据和交付口径统一

- 已完成：扩展 `scripts/evaluate_indicators.py`，读取当前多轮 benchmark、正式指标、manifest 和云端验证；输出状态、边界说明和源文件 SHA-256。
- 已完成：核实 Gallery 帧数为 190,191；此前缺口文档中的 191,195 是错误值。
- 已完成：最新 HTTPS/缓存结果已同步至课程报告正文、DOCX/PDF 和交付说明；PDF目录页码、字体、版心及来源哈希通过核验。
- 验收：机器报告中 no-result 保持 `null`/`not measured`；不覆盖正式实验或 benchmark 文件；源 JSON 哈希可复算。

### 阶段 1：识别准确率和样本覆盖

- 已完成 20 身份 YuNet 阈值 smoke：在既有 502 人 `threshold_selection` 中按固定种子选 20 人，对比记录过的阈值 0.90 与候选 0.85。子集结果从 18/20 到 19/20 Top-1，检测 Query 从 19/20 到 20/20；保留 400 条候选配对及逐 Query 对照。该子集已有历史使用，只能作探索性诊断，不是独立估计；最多 380 个 impostor pair 无法分辨 FAR=1e-3，因此未计算 TAR/FAR，不变更默认阈值。证据见 `data/ytf/experiments/ytf_arcface_yunet085_smoke20_20261101/`。
- 该 smoke 未读取或评分 test 媒体。正式 ArcFace test 仍为 Top-1 86.06%、TAR 86.65%；当前课题指标状态不变。本轮没有启动完整 502 人 selection。
- 在新的、授权的开发/selection 数据上分析无人脸 Query、检测失败、错误 Top-1 和身份排名；对失败类型分别统计。
- 在同一 selection 协议下单变量比较 detector、对齐/Query 选脸、模型和经过预先设计的帧聚合策略。已有负收益质量过滤/均值聚合不重复当作有效改进。
- 只有冻结模型、预处理、阈值来源和拒绝策略后，才运行新的独立 test。扩大身份数、Gallery 视频数和真实来源覆盖；重复帧或合成身份只可用于负载测试。
- 验收：Top-1、TAR@FAR、失败率及置信区间同时报告；保留无人脸分母、训练/selection/test 身份隔离和原始配对清单。
- 外部条件：合规的真实身份/视频来源、授权与伦理审批、额外存储和 CPU/GPU 算力。

### 阶段 2：数字信封、manifest 身份和批量密钥轮换

- 已完成格式决策与 opt-in 原型：见 `docs/adr/0002-video-key-envelope-and-rotation.md`。v2 每对象随机生成 SM4/MAC 主密钥材料，以 SM2 封装并记录 `key_id`、`key_version`；独立 KDF context 派生 HMAC-SM3 manifest tag。旧 v1 读写路径保持兼容，服务默认仍写 v1。
- 已完成接口和本地批量原型：`VideoKeyProvider`、`Sm2MemoryKeyProvider`、`store_enveloped_video`、`restore_enveloped_video`、`rewrap_enveloped_video`、`rotate_enveloped_batch`。批任务通过原子 JSON journal 记录对象、摘要、状态、重试次数和错误类型；只在新目标完成认证恢复后发布，源对象保持不变。
- 小样本验证记录见 `results/phase2_key_envelope_smoke_20261102_v2.json`；v1 兼容、v2 往返、篡改拒绝、rewrap 和批次续跑通过。该记录只证明合成对象上的功能路径，不证明生产密钥生命周期或规模性能。
- 待完成生产集成：可信 KMS/公钥目录、任务库中的对象与 key 状态、服务队列、manifest 摘要锚点/对象引用原子切换、缓存和备份迁移、故障恢复演练。当前 file-backed journal 不是生产任务队列，原型批处理不代表全局轮换已完成。
- 定义“旧密钥失效”的验收边界：仅在所有仍需保留的数据和缓存完成迁移、旧副本/备份处置策略确定后，测试旧密钥无法解密已迁移对象。不能同时声称可继续用旧密钥恢复未迁移对象且旧密钥全局失效。
- 选择性加密必须先比较全量 CBC+HMAC 与 codec-aware 方案，并列出可见的帧类型、长度、时间和结构信息；未完成泄漏分析前保持全量加密默认。
- 外部条件：可信 SM2 公钥注册/证书来源、私钥保管边界、密钥备份/恢复策略和运维责任人。

### 阶段 3：SM4 和在线时延

- 在同一设备/构建上分别测 SM4-CBC 原语、HMAC-SM3、完整内存封装、文件 I/O、单线程/多线程和冷/热检索；记录样本大小、版本、预热、轮数、中位数、P95、范围和峰值内存。
- 先 profiling 复制、GIL、原生调用和存储写入，再比较后端/块大小/线程数。每轮输出新 JSON，绝不挑单次峰值覆盖历史。
- 对端到端响应报告冷启动和缓存命中分布、P50/P95、错误率与样本量；缓存结果与无缓存相同配置逐项比对。
- 外部条件：目标云服务器、端侧设备矩阵、持续负载时长和真实 1080p 长视频。

### 阶段 4：密文检索与可撤销模板研究原型

- 先完成 `docs/adr/0001-private-search-architecture.md` 中的威胁模型、泄漏定义和候选方案比较，再选择可执行原型。
- 同时建立明文 ANN 速度/准确率基线；以小数据集验证加密相似度、Top-K、错误拒绝和恢复正确性。对 enclave、同态点积和结构化可搜索加密分别报告它们保护的内容与仍暴露的访问模式。
- 单独研究带密钥的可撤销特征变换，评估撤销重发后旧模板失效、同一人跨版本不可链接、跨用户碰撞、反演攻击和识别指标损失。
- 验收前不得把 TEE 内明文推理、磁盘加密向量或解密后检索称作“密文域检索”。
- 外部条件：威胁模型/泄漏容忍度决策、可用的国密或安全计算库、目标硬件以及隐私攻击评估数据。

### 阶段 5：规模化平台、租户和审计

- 从 SQLite 单实例演进前先做容量模型，再评估关系型数据库、对象存储、可恢复任务队列、幂等提交、配额、租户/视频授权和密钥隔离。
- 已完成可在当前仓库客观验收的第一步：统一审计写入生成 SHA-256 前向链，旧 SQLite 表迁移时按 ID 一次性补链，提供全链校验接口及含校验状态的 JSON/CSV/Markdown 导出。单测覆盖正常链、并发写入、内容改写、中间删除/重排、旧库迁移与导出。
- 后续仍需稳定 schema/关联 ID/可信时间源、独立外部不可变存储或锚点；用故障注入、日志删除/重排和跨库对账测量完整率。当前哈希链不能证明尾部未截断、整库回滚或抵御可重算本地数据库的攻击者。
- 在至少三类真实终端验证五种分辨率、上传/检索并发、错误率、日吞吐、重启恢复和审计报告生成率。合成负载只能验证容量，不能代替模型准确率测试。
- 外部条件：Linux 云主机/容器运行环境、实际网络、终端设备、对象存储与多租户测试账号。

## 验证原则

1. 正式 test、selection、历史 benchmark、manifest 和阈值均为只读输入。
2. 新实验写入新目录，保存配置、输入哈希、代码版本、环境、随机种子、失败样本及日志。
3. 目标口径不明确时先补定义和测量协议，不以改分母、阈值或样本口径追求 PASS。
4. 每项 PASS 必须同时有机制、样本、执行环境、统计量和可复算原始证据；功能测试不能代替规模和可靠性指标。
